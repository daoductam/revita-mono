## Scope

This matrix is the route-level contract baseline for compatibility-first migration. It contains 294 canonical NestJS routes and 24 frontend/desktop contracts not declared by NestJS. The request and response columns capture source declarations where available; legacy payload snapshots, observed status codes and confirmed consumers must be completed per priority flow before the corresponding Spring module is implemented.

The P0 static completion pack is maintained in `docs/plans/backend-api-migration/2026-10-13-p0-contract-pack.md`. It adds DTO fields, client evidence, state/security decisions and contract-test cases for the first implementation slices.

## Classification

- `canonical`: source-baseline route exists in a NestJS controller and must be exposed canonically under `/api/v1` in Spring.
- `compatibility-alias`: route is declared/called by frontend or desktop but is not a NestJS controller route; it needs an alias, a verified mapping, or an explicit client migration decision.
- `UNGUARDED/REVIEW`: source scan found no explicit `@Public`, JWT guard or role decorator; this is a security review item, not an authorization approval.
- `Promise<T>`: declared TypeScript return type only; it is not a verified wire-format snapshot.

## Version mapping

- The `Path` column is the legacy/source path currently used by NestJS or a client.
- For every business route whose path starts with `/api`, the Spring canonical target is obtained by replacing the leading `/api` with `/api/v1`. Example: `/api/auth/login` → `/api/v1/auth/login`.
- The legacy `/api/...` path remains available as a compatibility alias in phase 1 and must resolve to the same application service, authorization rule and response contract as `/api/v1/...`.
- The 24 `compatibility-alias` rows require an explicit v1 mapping review; path-name similarity alone is not sufficient evidence of semantic compatibility.
- After all active consumers migrate, `/api` aliases may emit `Deprecation` and `Sunset` headers before removal; this requires a measured consumer inventory and rollback path.
- `GET /` is not versioned. Swagger/OpenAPI and Actuator are operational endpoints outside the business API version.

## Required completion fields before implementation

- Confirm active consumer and source file.
- Capture one successful and one representative error response from NestJS.
- Record status codes, content type, pagination semantics and idempotency behavior.
- Confirm auth mode, roles and resource ownership rule.
- Assign canonical/alias owner and deprecation gate.

## Priority flow ownership

| Priority | Modules/routes | Required evidence before implementation |
|---|---|---|
| P0 Identity | auth, register, user, patient, patient-profile | login/refresh/me/profile payloads, JWT claims, ownership and error snapshots |
| P0 Operations | appointment, clinic, work-session, routing, take-number, counter-assignment | booking/check-in/queue state transitions, concurrency and desktop consumer tests |
| P0 Clinical | service, medical-record, template, prescription, medication-prescription, file-storage | role/ownership matrix, multipart/result payloads and clinical state transitions |
| P1 Payment | invoice-payment, PayOS webhook, statistics, doctor-rating | signature/idempotency evidence, payment state mapping and reconciliation |
| P1 Remaining | posts, admin, AI chatbot, external integrations | public/private visibility, admin auth and provider timeout/error contracts |
| P0 Realtime | five Socket.IO namespaces | event payloads, rooms, auth, reconnect and `patient_called` decision |
