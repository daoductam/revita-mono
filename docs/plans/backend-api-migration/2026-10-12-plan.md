# 1. Context

**Problem:**

`spring-revita-be` hiện mới là Spring Boot skeleton, trong khi `revita-be` có 294 HTTP route, 24 frontend/desktop compatibility route, 5 Socket.IO namespace và nhiều integration. Cần thay thế backend theo hướng compatibility-first để frontend và desktop hiện tại tiếp tục hoạt động trong phase đầu.

**Affected Modules:**

- `revita-be/src/**` — legacy HTTP controllers, guards, DTO và business behavior làm source of truth.
- `revita-fe/src/**` — web consumers và các route frontend chưa tồn tại trong Nest controller.
- `revita-desktop/src/**` — desktop consumers của queue, prescription, clinic room và Socket.IO.
- `revita-be/prisma/schema.prisma` — 45 model PostgreSQL và 9 enum cần mapping.
- `revita-be/src/websocket/**` — Socket.IO namespaces, rooms và realtime events.
- `spring-revita-be/**` — target Spring Boot implementation.

**Non-Goals:**

- Không refactor toàn bộ frontend trong phase 1.
- Không đổi global response envelope nếu làm hỏng payload legacy.
- Không chuyển Socket.IO sang STOMP trong phase 1.
- Không đổi business rule hoặc database ID strategy khi chưa có migration mapping và reconciliation.
- Không xóa route alias trước khi tất cả consumer đã chuyển sang canonical route.
- Không port mù toàn bộ controller trước khi contract và authorization matrix được duyệt.

# 2. Constraints

**Language:** `Java 21`

**Framework:** `Spring Boot` trong `spring-revita-be/pom.xml`

**Architecture:** `Modular layered architecture`

**Target package root:** `com.tamdao.spring_revita_be`

**Rules:**

- Dùng `/api/v1` làm canonical path cho Spring business API; giữ `/api` như legacy compatibility alias trong phase 1.
- Mọi `/api` alias và `/api/v1` route phải đi qua cùng application service, không nhân đôi business logic.
- Hỗ trợ 24 compatibility route được liệt kê trong mục 4 của spec.
- Phase 1 phải giữ request content type, response shape, status code và pagination legacy theo từng route.
- Dùng OpenAPI/contract artifact trước khi viết implementation controller.
- Không dùng fallback JWT secret; thiếu secret phải fail fast.
- CORS phải là allowlist theo environment, không dùng `origin: true` trong production.
- Mọi data access phải có authentication, role và ownership check phù hợp.
- Database migration phải backward-compatible, có backfill/reconciliation và rollback strategy.
- Không thêm dependency ngoài POM nếu chưa ghi rõ lý do và ảnh hưởng vận hành.

**Performance Budgets:**

- Chưa đặt ngưỡng mới trước khi đo baseline NestJS.
- TASK-002 phải ghi lại latency/error baseline cho các flow chính.
- TASK-013 chỉ cho cutover khi Spring không regression đáng kể so với baseline đã ghi nhận.

# 3. Conventions

> Các quy tắc này áp dụng cho mọi task implementation.

**Naming:**

- Package: `com.tamdao.spring_revita_be.<module>`.
- Class: `PascalCase`, ví dụ `AppointmentController`.
- Method/variable: `camelCase`.
- Endpoint path: route canonical mới dùng `/api/v1` + suffix legacy; `/api` chỉ dành cho compatibility alias trong phase 1. Route nghiệp vụ mới ngoài baseline dùng lowercase kebab-case.
- DTO: hậu tố `Request`, `Response`, `Query`, `PageResponse`.
- Entity: mapping rõ với Prisma model và không dùng entity trực tiếp làm API response.

**Layering:**

- `controller` chỉ parse request, validate và delegate.
- `service` giữ business rule và transaction boundary.
- `repository` chỉ truy cập persistence.
- `mapper` chuyển entity ↔ DTO.
- `exception` định nghĩa domain error và legacy error translation.
- Không để controller gọi repository trực tiếp.

**Error Handling:**

- Dùng `@RestControllerAdvice` cho error mapping.
- Giữ error shape mà từng legacy consumer đang dùng trong phase 1.
- Error nội bộ phải có machine-readable code và request/correlation ID.
- Không trả stack trace hoặc secret ra client.

**Logging:**

- Dùng SLF4J structured logging.
- Log request ID, route, actor ID, role, resource ID và outcome khi phù hợp.
- Không log password, JWT, OTP, payment signature hoặc payload nhạy cảm.
- Audit các access denied, ownership failure, webhook duplicate và state conflict.

**Testing:**

- Unit/integration framework: JUnit 5, Spring Boot Test, MockMvc/WebTestClient.
- Database integration: Testcontainers hoặc môi trường integration tương đương.
- Contract test chạy trên route canonical và alias.
- Web smoke test dùng `revita-fe`; desktop smoke test dùng consumer trong `revita-desktop`.
- Mọi task phải có acceptance criteria có thể kiểm tra được.

**Task Size:**

- Mỗi task implementation tối đa khoảng 200 LOC production code, không tính test.
- Task vượt giới hạn phải tách thành module/task nhỏ hơn.

# 4. Contracts

## Interface: `LegacyRouteContract`

```text
LegacyRouteContract {
  routeId:          String       — stable ID, e.g. HTTP-001
  method:            HttpMethod   — GET|POST|PUT|PATCH|DELETE
  legacyPath:        String       — source/client path, including /api when applicable
  canonicalV1Path:   String       — Spring canonical path under /api/v1
  sourceController: String       — Nest controller file and method
  consumers:        List<String> — web, desktop, mobile, proxy or unknown
  authMode:         AuthMode     — PUBLIC|JWT|ROLE
  allowedRoles:     Set<Role>    — explicit roles; empty only for public/JWT-only
  ownershipRule:    String       — resource ownership requirement
  requestContract:  SchemaRef    — DTO/query/path/multipart definition
  responseContract: SchemaRef    — legacy payload snapshot/schema
  statusCodes:      Set<Int>     — observed/expected statuses
  pagination:       Pagination   — page/limit, limit/offset, skip or none
}
```

**Pre-conditions:** route is present in Nest source or a verified consumer contract.

**Post-conditions:** Spring route returns the same observable contract in phase 1.

**Throws:** contract validation failure when method/path/consumer/schema is missing.

## Interface: `AliasRouteContract`

```text
AliasRouteContract {
  aliasPath:        String       — path currently called by a client
  canonicalV1Path:  String       — target Spring route under /api/v1
  method:           HttpMethod
  consumers:        List<String>
  payloadTransform: TransformRef — NONE or explicit request/response mapping
  deprecationPlan:  String       — owner, migration condition and removal gate
}
```

**Required aliases:** all 24 routes in spec section 4 must be classified as active, legacy, stale or unsupported before implementation.

## Interface: `AuthorizationRule`

```text
AuthorizationRule {
  routeId:          String
  authRequired:     Boolean
  roles:            Set<Role>
  ownership:        OWN_RESOURCE | ASSIGNED_RESOURCE | ROLE_WIDE | PUBLIC
  ownershipSource:  String       — token claim, relation or service rule
  deniedBehavior:   401|403
  auditRequired:    Boolean
}
```

**Required roles:** `ADMIN`, `DOCTOR`, `PATIENT`, `RECEPTIONIST`, `CASHIER`, `TECHNICIAN`.

## Interface: `StateTransition`

```text
StateTransition {
  aggregate:        Appointment|QueueTicket|WorkSession|Prescription|Payment|MedicationPrescription
  from:             String
  event:            String
  to:               String
  actorRoles:       Set<Role>
  preconditions:    List<String>
  idempotent:       Boolean
  conflictBehavior: 409|200-idempotent|other
}
```

## Interface: `MigrationMapping`

```text
MigrationMapping {
  legacyModel:      String
  targetEntity:     String
  idStrategy:       String       — preserve UUID/identifier unless approved otherwise
  enumMapping:      Map<String,String>
  relationMapping:  List<String>
  null/defaultRule: String
  backfill:         String
  reconciliation:   String
  rollback:         String
}
```

## Interface: `RealtimeContract`

```text
RealtimeContract {
  namespace:        String       — one of the five legacy namespaces
  clientEvent:      String
  serverEvent:      String
  roomPattern:      String
  authRule:         String
  payloadSchema:    SchemaRef
  reconnectRule:    String
}
```

## Shared DTO policies

- Phase 1 response: preserve actual legacy payload; do not wrap globally in `{data, meta}`.
- Phase 1 errors: preserve client-required status/body and add internal request ID where compatible.
- Pagination: preserve `page/limit`, `limit/offset` and `skip` per route until a versioned API is introduced.
- File upload: preserve `multipart/form-data`, file limits, MIME validation and path ownership rules.
- WebSocket: preserve Socket.IO namespace, event name, room pattern and acknowledgement behavior.

# 5. Target Architecture

**Components:**

- `Versioned API layer` — exposes 294 canonical `/api/v1` routes; `/api` legacy aliases and 24 frontend/desktop compatibility routes are adapters to the same application services.
- `Auth/Security layer` — JWT, refresh token, roles, ownership and CORS policy.
- `Module controllers` — auth, user, patient, appointment, clinic, queue, clinical, payment, content and AI.
- `Application services` — business rules, state transitions and transactions.
- `Persistence adapters` — PostgreSQL/JPA or jOOQ, Mongo drug catalog and Redis.
- `Realtime adapter` — Socket.IO-compatible namespaces, rooms and events.
- `Integration adapters` — PayOS, Google OAuth, Supabase, SNS, Resend, Gemini and FastAPI.
- `Contract test suite` — verifies route, payload, auth, state and realtime compatibility.

**Interaction Flow:**

```text
Web/Desktop client
  → /api/v1 canonical route or /api legacy/compatibility alias
    → Controller + validation
      → Authentication + role + ownership
        → Application service + state transition
          → Repository/integration transaction
            → Legacy-compatible response
              → Contract test and client smoke test
```

**Key Decisions:**

- Compatibility-first is the phase 1 migration strategy.
- Existing Nest behavior is the baseline, but known security defects are not copied to production.
- Socket.IO remains the realtime protocol until all consumers have a coordinated migration plan.
- Response normalization and API versioning are deferred until after the replacement is stable.
- Cutover is reversible through routing/API base URL configuration.

| 1 | Client calls a compatibility alias | Alias maps to canonical service and preserves legacy response | TASK-002, TASK-006–TASK-010 |

| 5 | CORS origin is not allowlisted | Browser request is rejected by policy | TASK-005 |

| 7 | Concurrent next-patient calls | At most one ticket is assigned; loser receives conflict/idempotent result | TASK-004, TASK-007 |
| 8 | Duplicate PayOS webhook | Verify signature and process exactly once/idempotently | TASK-004, TASK-009 |
| 9 | Socket reconnect after network loss | Restore allowed rooms without duplicate subscriptions/events | TASK-011 |
| 10 | Client listens to `patient_called` | Event is implemented and tested or contract is explicitly deprecated | TASK-002, TASK-011 |
| 11 | Multipart upload with invalid MIME/size/path | Reject safely and prevent path traversal | TASK-003, TASK-008, TASK-010 |
| 12 | Missing/duplicated relation after data migration | Reconciliation blocks cutover and produces actionable report | TASK-004, TASK-013 |
| 13 | External PayOS/Google/Supabase/Gemini/FastAPI outage | Stable error, timeout/retry policy and no partial state corruption | TASK-005, TASK-009, TASK-010 |
| 14 | Rollback during in-flight request | No irreversible dual-write; retry/reconciliation policy is applied | TASK-004, TASK-013 |
